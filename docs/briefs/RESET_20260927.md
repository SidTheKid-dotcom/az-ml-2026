- **Retrieval misses:** aliases at the S1's address, Indian native-script names (India S2 names are 24% native script),
  and empty-address names with typos.
- **Rejected candidates:** 80% have an empty address.
- **False links:** 51% have an empty address.
- **Shared-name empty-address records:** when the core name is shared by several S1s, the record is only ~4% true per
  pair. Colleague's generator measurement: decoys almost never have empty addresses (≤ 0.5%). So these records are
  probably true copies of *one of* the S1s sharing the name. The problem is assignment, not truth.

## 5. Generator facts (train labels) [M]

- **Country-independent:** 3.46 true links per S1 and a 5.58% no-match rate, identical in US and India.
- **Pool density:** train pool 4.67 records per S1 (74% true); test pool 5.8 (France 5.53).
- **Copy noise and decoy types** (colleague's `generator_params`):
  - true copies change the legal form rarely (US 2%, India 21%) and change digits 13–20% of the time;
  - same-name decoys change the house number (73–80%) and the legal form (45–70%);
  - same-address decoys substitute a name word (79–98%).
- **Source-specific noise:** US S2 addresses are 89% upper-case, S3 0%; S3 addresses have 53% word typos. The models
  never see which source a record comes from.
- **Legal-form class** (same core name + same address digits + fuzzy address): 99.85–99.99% true on B_REST.
- **French C2 behaviour:** C2 scores ~0.0003 on French legal-form variants (SARL/EURL/SASU added or changed). Rescoring
  confirms it is not a bug.

## 6. Dead ends (measured; do not repeat)

- **French rules:**
  - dropping street-disjoint links (one-character typos);
  - dropping the French uncertain band (break-even);
  - French candidate recovery for never-retrieved records (mostly decoys);
  - loosening the French threshold (look-alike band).
- **Post-scoring rules:** key moves and adds; count fill; expected-F0.5 decoding; mutual top-1; iterated best response;
  the resolver on old scores; a C2 floor on US/India.
- **Name-only rule:** extended past empty addresses; on top of the pair tree (−0.0003).
- **Pool structure:** cluster voting.
- **Test-density simulation** by withholding S1s (null effect).
- **Pseudo-labels:** strict pseudo-label French fine-tune (S2, never uploaded; lists get shorter).
- **The actual losers are information-poor additions.** Rule edits on existing scores are exhausted; the remaining gains
  need **better scores**, from better models, better inputs or better candidates.

## 7. What must be true for the leaders' 0.99 — hypotheses, ranked [H]

1. **A stronger pair scorer.** Qwen-0.6B matched C2 with 12× less data, so a larger Qwen reranker (4B, LoRA) trained on
   ≥ 1–2M hard arena pairs should lift both US/India and French transfer, since Qwen3 is strongly multilingual.
   *Test:* screen 4B on the same 416k pairs as 0.6B; compare on B_REST.
2. **French transfer through input canonicalization** (no training):
   - map French legal forms, street types and abbreviations, and départements to régions into forms C2 learned from
     US/India; fold accents;
   - rescore French pairs (~20 min GPU); France-only upload.
   - **Check first:** does the French test S1 file contain *sibling S1s* (same core name + same address, different legal
     form)? If it does, canonicalizing legal forms would merge real siblings.
3. **Synthetic French training data** (colleague's `synth_world` plus measured rates): positives are copies of French S1s
   with measured noise; negatives are only the measured decoy types. Mixed 50/50 with arena replay.
4. **Training on the full candidate distribution:** union plus address and empty-address branch pairs from partition A,
   plus a **source tag** (S2/S3) in the text, so the model learns aliases, native-script copies and co-located decoys.
5. **Assigning empty-address records** by *exact full name including legal form* uniqueness among S1s, plus per-S1
   copy-count structure. Needs a measurement: how many of the 25.8k rejected true empty-address links it separates.
6. **India native script:** a transliteration view (anyascii) as an extra input for the matcher.
7. **Stack everything** in the pair-tree decision layer (C2 + Qwen-0.6B + Qwen-4B + collective + new-pair features),
   cross-fit on B_REST halves.
